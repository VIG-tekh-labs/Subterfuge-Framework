# Public release and confidentiality policy

Subterfuge Framework is an independent, installable application. Public
code, documentation, tests, workflows, release notes, issues, pull requests,
CI output and **commit messages** must use vendor-neutral language for
optional automation integrations.

- Do not disclose private product names, internal project code names, private
  integration partners, customer information or personal workstation details.
- Describe integration through generic interfaces: an external automation
  agent, a caller-provided mission policy, explicit allowed actions and
  scoped targets and files.
- The public project must function without any private agent, account or
  proprietary connector. Privileged tasks still follow host OS permissions.
- Examine newly staged files, generated archives and proposed commit messages
  against a separate, non-committed internal confidentiality checklist before
  publishing.
- If an identifier was previously committed, removing it from HEAD does not
  remove older Git objects, hosted commit pages, clones, forks or caches.
  Coordinate any history rewrite explicitly; it can disrupt existing forks
  and cannot guarantee immediate removal of cached content.

Internal integration documentation belongs in private storage, not here.
